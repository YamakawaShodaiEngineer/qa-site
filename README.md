# Q&A サイト(Googleスプレッドシート連携・自治体ごとにシートを分ける方式)

URLの最後の値(例: `/渋谷区` の `渋谷区`)が、そのままGoogleスプレッドシートの**シート(タブ)名**として扱われ、そのタブに書かれたQ&Aだけを表示するサイトです。

- フレームワーク: Next.js 14 (App Router / TypeScript)
- スタイリング: Tailwind CSS
- データ: Google Sheets API v4(読み取り専用)
- 更新反映: 60秒キャッシュ(ISR)。シートを編集すると最大60秒でサイトに反映されます
- デプロイ先: Vercel(無料枠で運用可能)

## 1. スプレッドシートを準備する

**1つのスプレッドシート**を作成し、**自治体ごとにシート(タブ)を追加**します。タブ名がそのままURLになるので、URLとして使いたい名前をタブ名にしてください。

例: `渋谷区` タブと `港区` タブを作る場合

**渋谷区タブ(1行目はヘッダー、2行目からデータ)**

| A: question | B: answer |
|---|---|
| ごみの日はいつですか？ | 月・木曜日です。 |
| 住民票はどこで取れますか？ | 区役所2階の窓口です。 |

**港区タブ(同じ形式で、別タブに)**

| A: question | B: answer |
|---|---|
| 保育園の申込方法は？ | 区役所の子育て支援課へ。 |

- 表示順は、**シートに書いた行の順番のまま**表示されます(並び替えたい場合は、行そのものを並び替えてください)
- タブ名は自由につけられますが、日本語も問題なく使えます(URLでは自動的にエンコードされます)

**シートを共有設定から「リンクを知っている全員」→「閲覧者」に変更してください**(読み取り専用のAPIキーでアクセスするため、スプレッドシート全体で1回設定すればOKです)。

## 2. Google Sheets APIキーを取得する

前回設定済みの場合は、このステップは不要です(同じAPIキー・同じスプレッドシートIDをそのまま使えます)。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成(または選択)
2. 「APIとサービス」→「ライブラリ」から **Google Sheets API** を有効化
3. 「認証情報」→「認証情報を作成」→「APIキー」を作成
4. 「APIの制限」で **Google Sheets API のみ**に絞ることを推奨します

## 3. 環境変数を設定する

```bash
cp .env.local.example .env.local
```

```
GOOGLE_SHEET_ID=スプレッドシートのURLに含まれるID
GOOGLE_SHEETS_API_KEY=取得したAPIキー
```

(以前のバージョンにあった `GOOGLE_SHEET_TAB` は、この方式では不要になったため削除しました)

## 4. ローカルで実行する

```bash
pnpm install
pnpm dev
```

`http://localhost:3000` にアクセスすると、スプレッドシート内のタブ名一覧(自治体名一覧)が表示されます。`http://localhost:3000/渋谷区` のようなURLで、そのタブのQ&Aが表示されます。

## 5. Vercelにデプロイする(無料)

**① GitHubにリポジトリを作ってpushする**

このプロジェクトのフォルダをGitにする場合:

```bash
git init
git add .
git commit -m "first commit"
```

GitHub上で新しいリポジトリを作成し、表示される案内に従ってpushしてください(`git remote add origin ...` → `git push -u origin main`)。

**② Vercelにサインアップし、プロジェクトをインポートする**

1. [https://vercel.com](https://vercel.com) にアクセスし、GitHubアカウントでサインアップ/ログイン
2. ダッシュボードで「Add New...」→「Project」をクリック
3. 先ほどpushしたリポジトリを選び、「Import」をクリック

**③ 環境変数を設定する**

インポート画面(または後から「Settings」→「Environment Variables」)で、以下を追加します。

| Key | Value |
|---|---|
| `GOOGLE_SHEET_ID` | スプレッドシートのID |
| `GOOGLE_SHEETS_API_KEY` | 取得したAPIキー |

Vercelは`package.json`を見て自動的にNext.jsプロジェクトだと判定し、ビルドコマンドなどを自動設定してくれます。特別な設定は不要です。

**④ Deployボタンを押す**

数十秒〜数分でビルドが完了し、`https://プロジェクト名.vercel.app` のようなURLが発行されます。そのURLの末尾に自治体名を付けて(`https://プロジェクト名.vercel.app/渋谷区`)、動作を確認してください。

**以降の更新について**: GitHubに新しくpushするたびに、Vercelが自動で再デプロイします。スプレッドシート側の更新(タブの追加や質問の編集)は、コードの変更なしに、60秒以内に反映されます。

## 仕組みのポイント(変更点)

- 以前のバージョン(1シート + slug列で絞り込み)から、**シート(タブ)そのものを自治体単位に分ける方式**に変更しました
- `lib/sheets.ts` の `fetchAllSlugs()` は、以前は「slug列の重複を除いた一覧」でしたが、今は **spreadsheets.get というAPIでシート(タブ)名の一覧を直接取得**しています
- `fetchQAForSlug(slug)` は、以前は「全件取得してからJavaScript側でfilterする」方式でしたが、今は **`'{slug}'!A2:B` のようにAPIへのリクエスト自体でタブを指定**しています。無関係なタブのデータは一切取得しないため、自治体の数が増えても1回の通信量は増えません
